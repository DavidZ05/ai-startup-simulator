# AI Startup Simulator

A single-player, turn-based startup game. Build a company through monthly decisions, research, hiring and market expansion. React provides the workbench; an Express/SQLite server owns all gameplay state.

## Local development

Requires Node.js 24 and npm.

```sh
npm ci
npm --prefix server ci
cp server/.env.example server/.env
npm run dev:all
```

Open http://localhost:5173 (http://127.0.0.1:5173 also works). Register an account: username 3–32 characters, password at least 8 characters and at most 72 UTF-8 bytes. Existing accounts remain usable. There are no built-in accounts.

The frontend proxies `/api` to port 3001. Both processes must be running. Reports are generated by the game engine and require no external AI key. The installable app can cache its public shell; gameplay and account access require a connection.

Development generates a temporary JWT signing key when no valid key is configured; restarting then requires signing in again. To keep sessions across restarts, generate a random key and set `JWT_SECRET` in `server/.env`:

```sh
node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"
```

## Production / Docker

One container serves the built frontend, API and SQLite database on port 3001. The image includes the compiled shared engine and runs as an unprivileged user.

```sh
export JWT_SECRET='your-generated-random-key-at-least-32-characters'
export CORS_ORIGIN='http://localhost:3001'
docker compose up --build -d
```

Replace the example JWT value with the generated random value. Production refuses missing, short or placeholder signing keys. Set `CORS_ORIGIN` to the actual public origin; separate multiple origins with commas. A reverse proxy should terminate HTTPS for public deployments.

Compose mounts `./server/data` at `/app/data`, preserving the same local database directory used by development. Back up this directory before deployment. Never share a live database between independently deployed copies of the app. Credentials, databases, local agent memory and preview artifacts are excluded from the image and Git.

Without Docker:

```sh
npm run build
npm run build:server
cd server
# Configure NODE_ENV, JWT_SECRET, CORS_ORIGIN, and FRONTEND_DIST=../dist
npm start
```

`DATABASE_PATH` defaults to `./data/game.db` relative to the server working directory. `FRONTEND_DIST` is optional in development. `VITE_API_URL` can override the same-origin API base at frontend build time.

## Validation

```sh
npm run check
```

This runs TypeScript checks, lint, all engine/UI/API tests, and both production builds. API tests listen on temporary loopback ports and use in-memory SQLite; they never touch a real account or save. See [DESIGN.md](DESIGN.md) for architecture and invariants, and [API.md](API.md) for endpoint contracts.

## Data maintenance

The UI’s cleanup operation removes only the signed-in user’s inactive games older than 90 days. It also removes their associated history and ranking entries. Deleting a company or all game data uses a transaction with foreign-key-safe ordering.

Global automatic cleanup is disabled by default. Operators may set `AUTO_CLEANUP=true` to clean inactive games older than 90 days at startup, or run the maintenance command explicitly:

```sh
npm --prefix server run cleanup -- 90
```

This command is global. Stop the app and back up its database before manual maintenance. Local tool memory and screenshots are ignored; they are not part of the app.
